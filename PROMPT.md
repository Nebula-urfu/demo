# Промпт для Claude Code: демо-прототип YKit на Nuxt

Скопируй всё ниже в первое сообщение Claude Code, запущенного в корне этого набора.

---

Ты создаёшь **минимальный демонстрационный прототип** веб-сайта YKit: сервис для небольших управляющих компаний (УК), где ИИ-помощник проводит заявку жителя от фото до готового пакета документов закупки, а человек проверяет и утверждает результат на каждом ключевом шаге.

Прототип нужен только чтобы **показать задумку**. Реальной работы в нём нет.

## Жёсткие ограничения

1. **Только Nuxt.** Один проект Nuxt: интерфейс на Vue и серверная часть на Nitro (`server/api`). Никаких отдельных сервисов, Java, Python, Docker, брокеров.
2. **База данных только SQLite**, один файл `data/demo.db`.
3. **Вход принимает любые данные.** Любой логин и пароль, пустые поля тоже. Реальной аутентификации нет, токен непрозрачный. Роль выбирается на экране входа или определяется по правилам из `docs/MOCKS.md`, раздел 1.
4. **Все ответы «внешних» частей подделаны.** ИИ, Documents, Reference Data, Notifications это мок-реализации за интерфейсами. Правила и фикстуры в `docs/MOCKS.md`.
5. **Интерфейс по макету Figma:** https://www.figma.com/design/AqhhX0BeIoygkaIjKa9WXR/YKit?node-id=0-1&t=LIchbkDb9OvpOrDO-1 . Как получить макет и что делать, если он недоступен, написано в `docs/DESIGN.md`. **Не придумывай внешний вид, которого нет в макете.**
6. **Контракт сервера** `contract/core-api.openapi.yaml` (27 операций) это источник истины для путей и схем. Его не менять. Лишние эндпоинты только под `/api/v1/dev/`.
7. Сервер слушает только `127.0.0.1`, во всех ответах заголовок `X-Demo-Mode: true`, в интерфейсе виден постоянный баннер «Демо: данные вымышленные».
8. Прототип не ходит в интернет: без CDN, внешних шрифтов, аналитики и внешних картинок.

## Порядок чтения

1. `CLAUDE.md`
2. `docs/SPEC.md` (цели, архитектура, решения)
3. `docs/DESIGN.md` (макет) и `docs/SCREENS.md` (экраны по ролям)
4. `docs/API.md`, `docs/DATA.md`, `docs/MOCKS.md` (поведение сервера, схема SQLite, моки)
5. `docs/DEMO.md` (сценарий демонстрации)

## Фазы

Делай по порядку. После каждой фазы запускай проверку и коротко записывай итог в `docs/PROGRESS.md`.

- **Фаза 0. Макет и стек.** Получи макет по `docs/DESIGN.md`, выпиши в `docs/DESIGN-NOTES.md` список экранов макета, цвета, шрифты, компоненты и сопоставь экраны макета с `docs/SCREENS.md`. Выясни актуальные стабильные версии Node, Nuxt, Tailwind и драйвера SQLite, не опирайся на память. Расхождения с `docs/SPEC.md` запиши в `docs/DECISIONS.md`. Если макет недоступен, **не переходи к фазам 4 и 5**, сделай фазы 1–3 и сообщи об этом в итоговом отчёте.
- **Фаза 1. Каркас сервера.** Проект Nuxt, `server/db` (подключение, `schema.sql` из `docs/DATA.md`, сброс), загрузка настроек из переменных окружения, заголовок `X-Demo-Mode`, ошибки в формате `application/problem+json`, определение текущего пользователя по токену, проверка ролей, фильтр по `org_id`.
- **Фаза 2. Эндпоинты Core.** Все 27 операций контракта и `/api/v1/dev/*` по `docs/API.md`: автомат состояний шагов, версии ТЗ и НМЦ, согласования и неизменяемый журнал, сравнение КП, расчёт НМЦ.
- **Фаза 3. Моки.** Интерфейсы `AiGateway`, `DocumentsGateway`, `ReferenceGateway`, `NotificationsGateway` и мок-реализации, фикстуры в `server/mock/*.json`, обработчик заданий ИИ (плагин Nitro, опрос таблицы `ai_jobs` каждые 200 мс), журнал событий. Затем `scripts/demo.sh` и тест `tests/smoke.test.ts` по `docs/DEMO.md`. **Без интерфейса сценарий API уже должен проходить до `DEMO OK`.**
- **Фаза 4. Интерфейс: основа.** Токены дизайна из макета в одном месте (конфиг Tailwind или CSS-переменные), общие компоненты, вход, каркас с навигацией по ролям, баннер демо, composable `useApi` (добавляет токен, разбирает `problem+json`).
- **Фаза 5. Интерфейс: экраны.** Экраны из `docs/SCREENS.md` для трёх ролей. Состояния шагов, ожидание результата ИИ (опрос раз в секунду, пока шаг в `PROCESSING`), ошибки, пустые списки. Проверка на телефонной ширине 375 px и на ноутбучной 1280 px.
- **Фаза 6. Проверка и сдача.** Типы без ошибок (`nuxt typecheck`), `npm test`, `bash scripts/demo.sh` до `DEMO OK`, ручной проход UI по `docs/DEMO.md` с проверкой в браузере. Обнови `README.md` в корне проекта: как запустить и что показывать.

## Правила

- **Не угадывай.** Нет данных в документах или макете: выбери простейший вариант, запиши в `docs/DECISIONS.md` и перечисли в итоговом отчёте. Не придумывай поля, экраны и тексты, которых нет ни в макете, ни в `docs/SCREENS.md`.
- Все мок-тексты и цены с пометкой «ДЕМО». Никаких реальных норм, номеров ГОСТ и СП, статей законов, реальных цен и организаций.
- ИИ ничего не утверждает: его результат всегда черновик, утверждает проверяющий.
- Каждый запрос к базе фильтруется по `org_id` из сессии.
- Журнал согласований только добавляется (триггеры из `docs/DATA.md`).
- Сервер синхронный и простой: без ORM, без кэшей, без очередей кроме таблицы `ai_jobs`.
- Не добавляй: реальную аутентификацию, push-уведомления, PWA, загрузку настоящих файлов, i18n, тёмную тему, анимации сверх макета.
- Код и идентификаторы на английском, тексты интерфейса и фикстуры на русском.
- Команды в документации и скриптах оболочки пиши совместимыми с **fish**: переменные окружения через `env VAR=значение команда`, не `VAR=значение команда` и не `export`. Файл `scripts/demo.sh` это bash и запускается как `bash scripts/demo.sh`.
- Не делай коммиты, пока не попросят.

## Определение готовности

1. `npm install` и `npm run dev` запускают сайт на `127.0.0.1:3000` без ручных шагов.
2. Вход принимает любые данные, включая пустые, и ведёт на экран роли.
3. Все 27 операций контракта отвечают по схеме OpenAPI.
4. `bash scripts/demo.sh` проходит весь сценарий `docs/DEMO.md` и печатает `DEMO OK`.
5. В интерфейсе можно пройти путь от заявки жителя до `COMPLETED` под тремя ролями (житель, сотрудник, проверяющий).
6. Видно состояния `PROCESSING`, `DRAFT_READY`, `IN_REVIEW`, `NEEDS_REWORK`, `AI_FAILED` и `APPROVED`.
7. Изоляция по организации работает: заявка другой организации для пользователя это `404`.
8. Интерфейс соответствует макету (или честно сказано, что макета не было, и фазы 4–5 не сделаны).
9. Ни один запрос из браузера не уходит на внешний адрес.
10. `nuxt typecheck` и `npm test` проходят.
